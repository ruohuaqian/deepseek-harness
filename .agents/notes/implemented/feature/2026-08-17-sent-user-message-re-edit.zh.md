# Agent Note: 通过切在轮次之前的 fork 重编辑已发送的 user 消息

Status: implemented

[English](2026-08-17-sent-user-message-re-edit.md) | 中文

## 问题

已定稿的 user 气泡无法被修正。编辑控件曾因是无效存根而被移除；user 气泡上的分支控件也被移除，因为按消息 seq fork 会包含该回答——与从自己的提示词重问相反。用户打错命令、或想在工具已经跑过之后重试时，没有一条会把回撤说清楚的诚实路径。若把源会话留在列表里并标成 `(1)`，读起来就像新开了一段对话，不符合重编辑的用法。

## 决策

编辑只出现在已定稿的 `user` 气泡上（不包括待处理或已消费的 steering）。点击后打开页内确认：当前对话撤回到这条消息之前；这条消息及其后内容离开当前列表；已经对文件或环境做过的修改不会自动撤销。确认后调用 Host `session.fork`，带上 `cut: 'before-turn'` 和该 user 消息的 `atSeq`，子会话种子结束在该轮 `turn/start` 之前——即使源会话上该轮仍在进行。随后 client 用源标题在源 Workspace 槽位打开子会话，把原文预填进输入框，取消仍在运行的源轮次，并归档源会话，使侧栏仍只显示一段对话。会话日志保持只追加；归档隐藏源会话，并不截断它。

此前没有任何轮次时，空前缀子会话是合法的（重编辑第一条提示词）。原消息上的图片附件不会被复制进输入框。assistant 回答下的分支仍递增兄弟标题，并保留源会话列表项。

## 曾考虑的替代方案

**原地改写已定稿的 user 消息。** 会话日志是只追加的；改写一条已被消费的提示词，会让模型 transcript（文本记录）与持久事件、以及该轮已经做过的工具工作失步。

**把源会话留在列表里并递增 `(1)`。** 那是分支手势。用在编辑上会表现为第二段对话，而不是覆盖当前对话。

**把编辑接到队列编辑器上。** 队列编辑的是尚未发送的项。已定稿的 user 消息已经进入 transcript 和模型上下文。

**fork 之后自动发送编辑后的文本。** 只预填不发送，能让修正可见，也允许用户在开启新轮次前改得比原来的笔误更多。

**确认后让源轮次继续跑。** 被放弃的轮次会在已归档的行后面继续消耗模型和工具。取消会停下这项工作；已经发生的文件或环境副作用仍然不会回滚。

**要求勾选风险确认框。** Full access 用该门槛是因为它扩大权限。这次确认谈的是对话谱系，不是授予新能力。

## 后果

Web 可以修正已发送的提示词，而不在侧栏多出一条兄弟会话。assistant 回答下的分支不变（含轮次裁切、递增标题、保留源会话）。包测试钉住确认对话框、Host 的切在轮次之前裁切（包括开放轮次和第一条提示词的空种子）、输入框预填，以及编辑不传 `increaseTitle`；message-actions 的 web aria golden 在 user 气泡上包含编辑控件。
